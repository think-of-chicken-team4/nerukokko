# ねるコッコ 完全仕様書

創造設計 4班

## 1. 製品コンセプト

にわとりと一緒に整える朝と夜。

睡眠不足は現代人の大きな課題であり、既存の睡眠トラッカーは無機質で続けにくく、計測から改善提案までを一体化した製品は多くない。「ねるコッコ」は、計測・記録・改善提案・朝の会話を1台で完結し、装着不要で毎日楽しく続けられる睡眠改善体験を提供することを目標にする。

- **利用対象者**：睡眠に悩みを抱える10〜30代の学生・社会人
- **キーワード**：睡眠改善／キャラクター／生活習慣
- **制限事項**：小児への光刺激に注意、Wi-Fi環境が必要（鶏ユニット）、カメラは非搭載（プライバシー配慮）

3ユニット構成：

| ユニット | 役割 |
|---|---|
| 🐔 にわとり本体 | LED光目覚まし、スピーカー・マイクによる音声会話、温湿度・照度・ミリ波レーダー計測、たまごとのBLE受信・クラウドとの通信を担う中枢 |
| 🥚 たまごセンサー | 加速度センサーによる寝返り検出、マイクによるいびき・寝言検出、装着不要でベッドに置くだけ |
| 🪺 巣（充電ステーション） | たまごの充電。充電開始検知＝アラーム停止（二度寝防止） |

主な機能：起床アシスト／音声会話／睡眠計測（寝返り・呼吸）／音響パターン検出（いびき・寝言）／環境モニタリング／睡眠提案（カレンダー連携）／二度寝防止／睡眠総括（アプリでグラフ・履歴確認）

## 2. ハードウェア構成

### 2-1. 鶏（にわとり）ユニット

| 項目 | 内容 |
|---|---|
| メインボード | Raspberry Pi 3 Model B V1.2（学校保有品、無償） |
| 採用理由 | ミリ波レーダー（Acconeer A111）の公式対応プラットフォームがRaspberry Pi向けだったため。当初は鶏・たまご共にESP32を使う計画だったが、学校にある使えるものを探した結果この構成に変更した |
| ミリ波レーダー | Acconeer A111搭載モジュール（SSCI-067232、技適対応）、呼吸検知用 |
| マイク | SPH0645LM4H（I2S、学校保有品） |
| スピーカー | ADA-4445 |
| スピーカーアンプ | M0082-9728（Adafruit MAX98357A、マルツ経由） |
| LED | ×2（SSCI-013987） |
| ボタン | 押しボタンスイッチ TVDP01-6.5（会話起動用、通称「トサカボタン」） |
| 電源 | ACアダプター（MicroUSB、5V/3A、SSCI-028011） |
| 温湿度・照度センサー | M0235-1747（温湿度）、SEN0097（照度） |

### 2-2. たまごユニット

| 項目 | 内容 |
|---|---|
| メインボード | ESPr Developer 32（SSCI-032100、ESP-WROOM-32搭載） |
| マイク | ADA-4346（PDM方式）。I2Sマイク（SPH0645LM4H等）が業界的に品薄・生産終了が相次いだため採用 |
| 加速度センサー | SEN0142（寝返り検知用） |
| リポバッテリー | DTP603450 |
| 充電モジュール | SFE-PRT-14380（MCP73831搭載）。STATピンで充電状態（起床/就寝）を検知 |
| 磁石式充電コネクタ（受け側） | 303C-C4515-40-02-1 |
| ユニバーサル基板 | ICB-288（72×47mm、3枚） |

## 3. ソフトウェア構成

詳細は `docs/software-spec.md`（DBスキーマ全14テーブル・データフロー・フローチャート）を参照。概要は以下の通り。

| 領域 | 決定内容 |
|---|---|
| Webアプリ | Next.js（React + TypeScript） |
| 鶏ユニット | Raspberry Pi 3 Model B、Python、Acconeer公式SDK、bleak |
| たまごファームウェア | PlatformIO、NimBLE-Arduino |
| バックエンド／DB | Supabase（PostgreSQL + Edge Functions + Realtime + Auth + Storage） |
| 鶏⇔サーバー通信 | HTTP REST |
| 鶏⇔たまご通信 | BLE（詳細は `docs/ble-protocol.md`） |
| AI連携 | Gemini API |
| カレンダー連携 | Google Calendar API |
| 音声認識／音声合成 | Google Cloud Speech-to-Text／Text-to-Speech |
| クラウド費用 | Google AI Studio無料枠内で運用（GCP課金アカウントは紐付けない） |

音声会話の起動はトサカ（物理ボタン）のみで、ウェイクワード検出は今後の課題として見送っている。応答までのラウンドトリップ・レイテンシは約3〜5秒と見積もっている。

睡眠スコアは以下の重み付けで算出する（算出アルゴリズムの参考文献・詳細検証はB担当にて対応中）：

```
睡眠スコア = 40×睡眠効率 + 15×寝返りバランス + 15×静音度 + 15×呼吸安定性 + 15×環境適合度
```

## 4. 開発体制

### 4-1. メンバー
- リーダー：松島 蓮
- サブリーダー：内海 圭吾
- HW担当：松島 蓮、田村 愛琉、浅井 蒼輝
- SW担当：内海 圭吾、岡田 蓮、渡邉 健太

### 4-2. SW担当の役割分担
- A：フロントエンド担当（スマホ/Webアプリ画面実装、状態管理、グラフ、デバイスシミュレーター機能）
- B：バックエンド／AI担当（サーバー・DB・API設計、スコアアルゴリズム、Calendar/Gemini/STT・TTS連携）
- C：組み込み担当（鶏・たまごファームウェア：センサー処理、BLE通信、省電力設計）— 岡田 蓮

### 4-3. 開発の進め方
- `main` ブランチは保護されており、直接pushはできません。変更は必ずブランチを切ってPull Requestを作成し、レビュー承認後にマージする
- タスク管理はGitHub Projects（カンバンボード）＋ Issueで行う。ラベルは `frontend` `backend` `firmware` を使用
- 開発スケジュールは創造設計デザインレビュー資料のガントチャートを参照（4月〜2月、30週間）
