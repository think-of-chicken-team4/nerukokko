### 5-2. ホームのフェーズ判定

上から順に判定する。

| 条件 | フェーズ |
|---|---|
| 進行中（`in_progress`）のセッションがあり、現在時刻 < `planned_wake_time` | 睡眠記録 |
| 進行中のセッションがあり、現在時刻 ≥ `planned_wake_time` | 起床制御 |
| 直近12時間以内に完了（`completed`）したセッションがあり、現在時刻が17:00より前 | 朝の振り返り |
| ユーザーが「就寝準備へ進む」を押した（画面内の状態） | 就寝準備 |
| それ以外 | 夕方確認 |

### 5-3. 睡眠セッションのライフサイクル（提案 → §9 Q3 で確定）

1. 就寝準備画面で「眠りにつく」→ Webアプリが `sleep_sessions` を作成（`status = in_progress`、`planned_wake_time` = 次のアラーム時刻）
2. 鶏は `device-sync` でセッションIDと起床時刻を受け取り、計測データを `session_id` 付きで送る
3. 起床時刻になると鶏がローカルでアラームを鳴らす（在床確認はしない）
4. たまごが巣に戻る → BLE で鶏へ → 鶏がアラームを止め、`charge_start` を即時 POST
5. サーバーがセッションを完了（`actual_wake_time`・`end_time`・`status = completed`）→ スコア算出＋コメント生成 → Realtime でアプリに反映
6. 「中止」した場合は `status = aborted`

## 6. 睡眠スコア算出仕様（初期版）

デザインレビュー資料の式を採用する。各要素を0〜100点で出し、重みを掛けて合計する。

```
スコア = 0.40×睡眠効率 + 0.15×寝返りバランス + 0.15×静音度 + 0.15×呼吸安定性 + 0.15×環境適合度
```

| 要素 | 使うデータ | 算出方法（初期値。実機データで調整する） |
|---|---|---|
| 睡眠効率 | `sleep_sessions`、`motion_events`、`presence_events` | 効率(%) = 総睡眠時間 ÷ 総就床時間 × 100、点数 = min(100, 効率 ÷ 85 × 100)。就床時間 = 開始〜起床。入眠 = 開始後に「寝返りのない状態が15分続いた」最初の時刻。入眠後に離床していた時間は睡眠時間から除く |
| 寝返りバランス | `motion_events` | 100 − \|回数 − 15\| × 2 |
| 静音度 | `audio_events` | 100 − 1時間あたりの回数 × 10 |
| 呼吸安定性 | `breathing_readings` | 100 − 呼吸数の標準偏差 × 10 |
| 環境適合度 | `environment_readings` | 温度16〜29℃かつ湿度40〜60%だった計測の割合 × 100 |

- 各要素は 0〜100 に丸める。**データがない要素は除外し、残りの重みで割り直す**（センサー未接続でもスコアが出るようにするため）。
- ラベル：85点以上「ぐっすり眠れました」、65点以上「まずまずの睡眠でした」、それ未満「やや浅い睡眠でした」。
- 算出は Edge Function 内の純粋関数にし、単体テストを書く。
