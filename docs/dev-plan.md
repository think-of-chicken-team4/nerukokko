### ローカル環境の起動（毎回）
Docker Desktop を起動してから、それぞれ別のターミナルで：
- `cd server && npx supabase start -x imgproxy,logflare,vector,supavisor`
- `cd server && npx supabase functions serve`
- `cd app && npm run dev` → http://localhost:3000（テスト用アカウントは `app/CLAUDE.md`、実機の代わりは設定 →「デバイスシミュレーターを開く」）
- 起動したら `cd server && npx supabase status` で動いているか確かめる（`supabase start` の失敗は出力の途中に出て見落としやすい）。

### 今わかっている注意点
- Docker Desktop の仮想ディスク（64GB）が、ほかのプロジェクトのイメージで一杯になりやすい。`no space left on device` で起動できないときは、消してよいものを田村さんに確認してから消す。
- `app/` でパッケージを追加・更新したら `npm ci --dry-run` を通す（`package-lock.json` が食い違うと CI が落ちる）。
- Realtime は `subscribeAsUser()` で購読する（`app/CLAUDE.md`）。
- デスクトップアプリを再起動するとブラウザの保存内容が消え、シミュレーターが「未登録」になる。そのときは「仮想の鶏・たまごを登録」を押し直す（トークンが作り直される）。また、処理中（ボタンが押せない間）に押したボタンは無視される。
- 仕様書と違うこと・仕様書にないことを決めたら、`docs/spec-changes.md` にも1行追加する（CLAUDE.md §4）。
- ローカルの DB には、週間の画面を確かめるためのテスト用の夜（10/11〜10/15）、就寝提案、デモの確認用アカウント（`demo@example.com`、app/CLAUDE.md）を入れてある。消したいときは `npx supabase db reset`。
- ローカルの DB の Vault に、定期実行用の `project_url`・`secret_key` を入れてある（`db reset` で消えるので、そのときは server/CLAUDE.md の手順で入れ直す）。
- カレンダー連携をローカルで試すときは、Webアプリを **`localhost:3000`** で開く（`127.0.0.1` だと Google に登録した戻り先と合わない）。
- 同じ日にシミュレーターで何度も試すと「一晩分」が短くなる。`cd server && npx supabase db reset` で初期化できる（テスト用アカウントも消えるので作り直す）。

### 5-3. 睡眠セッションのライフサイクル（提案 → §9 Q3 で確定）

1. 就寝準備画面で「眠りにつく」→ Webアプリが `sleep_sessions` を作成（`status = in_progress`、`planned_wake_time` = 次のアラーム時刻）
2. 鶏は `device-sync` で起床時刻を受け取り、計測データを送る（どのセッションに入れるかは、サーバーが計測時刻から判定する。`docs/api-spec.md` §3-1）
3. 起床時刻になると鶏がローカルでアラームを鳴らす（在床確認はしない）
4. たまごが巣に戻る → BLE で鶏へ → 鶏がアラームを止め、`charge_start` を即時 POST
5. サーバーがセッションを完了（`actual_wake_time`・`end_time`・`status = completed`）→ スコア算出＋コメント生成 → Realtime でアプリに反映
6. 「中止」した場合は `status = aborted`

## 6. 睡眠スコア算出仕様（初期版）

デザインレビュー資料の式を採用する。各要素を0〜100点で出し、重みを掛けて合計する。

```
スコア = 0.40×睡眠効率 + 0.15×寝返りバランス + 0.15×静音度 + 0.15×呼吸安定性 + 0.15×環境適合度
```

| 要素 | 使うデータ | 算出方法（初期値。実機データで調整する） |
|---|---|---|
| 睡眠効率 | `sleep_sessions`、`motion_events`、`presence_events` | 効率(%) = 総睡眠時間 ÷ 総就床時間 × 100、点数 = min(100, 効率 ÷ 85 × 100)。就床時間 = 開始〜起床。入眠 = 開始後に「寝返りのない状態が15分続いた」最初の時刻。入眠後に離床していた時間は睡眠時間から除く |
| 寝返りバランス | `motion_events` | 100 − \|回数 − 15\| × 2 |
| 静音度 | `audio_events` | 100 − 1時間あたりの回数 × 10 |
| 呼吸安定性 | `breathing_readings` | 100 − 呼吸数の標準偏差 × 10 |
| 環境適合度 | `environment_readings` | 温度16〜29℃かつ湿度40〜60%だった計測の割合 × 100 |

- 各要素は 0〜100 に丸める。**データがない要素は除外し、残りの重みで割り直す**（センサー未接続でもスコアが出るようにするため）。
- **睡眠効率・寝返り・呼吸・環境のどれもない夜はスコアを出さない**（`score = null`、画面は「計測できませんでした」）。静音度だけでは計算しない（いびき0回が「静か」なのか「計測なし」なのか区別できないため。Q11・T-210）。このとき `score_details` は保存するので、「計算中」（`score_details` もない）と区別できる。
- ラベル：85点以上「ぐっすり眠れました」、65点以上「まずまずの睡眠でした」、それ未満「やや浅い睡眠でした」。
- 算出は Edge Function 内の純粋関数にし、単体テストを書く。
