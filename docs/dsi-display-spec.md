# 鶏の DSI ディスプレイ（目の表情）仕様案

最終更新：2026-10-23　作成：田村（Claude Code と作成）　**状態：案（班で決める前のたたき台）**

`docs/dev-plan.md` §9 Q10・`docs/spec-changes.md` P-07・Issue #28 の検討用。決まったら、この文書を「確定」にして決定ログに移し、開発を始める。
岡田さんの試作（ブランチ `ren-eye-display`、`firmware/chicken/eyes/`）の表情（通常・眠い・うれしい・起こす）と昼夜の切り替えを土台にしている。

**決めてほしいこと**は §7 にまとめた。各項目に Claude のおすすめを書いてある。

---

## 1. 前提

- 部品：5インチ DSI ディスプレイ（800×480、静電容量タッチ）。Raspberry Pi 3B に DSI ケーブルでつなぐ（ドライバ不要、10/9 確認済み）。
- 表示するのは**にわとりの目だけ**（文字・時計・数字は出さない）。スコアや記録は Webアプリで見る。
- 鶏の本体（`main.py`：BLE・レーダー・アラーム・通信）の動きを邪魔しないこと。Pi 3B は非力なので、表示の負荷を小さくする。
- **寝ている人の邪魔をしないこと**（画面の光は睡眠の質を下げる）。

## 2. 表情と、いつ出すか

上ほど優先する（例：記録中にアラームが鳴ったら「起こす」）。

| 優先 | 鶏の状態 | 表情 | 画面の明るさ | 本体のどこで分かるか |
|---|---|---|---|---|
| 1 | アラームが鳴っている | **起こす**（WAKE：目を大きく、脈打つ） | 最大 | `alarm.ringing` |
| 2 | ボタンで話しかけられて録音中 | **聞いている**（LISTEN：目を少し大きく、まばたき少なめ）〔新規〕 | 通常 | `_talk()` の録音中 |
| 3 | 返事を考えている（サーバー待ち） | **考え中**（THINK：視線を上に）〔新規〕 | 通常 | `_talk()` の送信〜返事 |
| 4 | 話している（返事・夕方の提案・朝のコメント） | 朝のコメントは**うれしい**（HAPPY）、それ以外は**通常** | 通常 | `_say()`・返事の再生中 |
| 5 | 記録中（眠っている） | **眠り**（SLEEP：目を閉じる）〔新規〕 | **消灯**（おすすめ）か最低 | device-sync の `session` が `in_progress` |
| 6 | 夕方〜就寝予定（19時〜） | **眠い**（SLEEPY） | 暗め | 時刻（19時以降）か、夕方の提案を話したあと |
| 7 | それ以外 | **通常**（NORMAL） | 周りの明るさに合わせる | — |

- 〔新規〕の3つ（LISTEN・THINK・SLEEP）は試作にない。いらなければ、LISTEN・THINK は通常、SLEEP は消灯だけでもよい（§7 の Q10-1）。
- サーバーにつながらないときの表情（困り目など）は作らない（おすすめ）。アラームは手元の時刻で鳴るので、寝る人が困ることはない。
- 「うれしい」をスコアの高さで出し分けるには、device-sync の `announcements` にスコアを足す必要がある（通信の契約の変更）。まずは朝のコメントのときは常に「うれしい」にする（おすすめ）。

## 3. 明るさ

- **記録中は画面を消す**（バックライト 0。おすすめ）。アラームが鳴ったら点けて「起こす」を出す。
- 記録中でないときは、照度センサー（BH1750）の値で決める：暗い部屋（10 lx 未満）では暗め、明るい部屋（30 lx 以上）では通常（試作の `LUX_DARK_BELOW`・`LUX_BRIGHT_ABOVE` と同じ。間はヒステリシス）。照度がなければ時刻（22時〜6時が夜）。
- バックライトは `/sys/class/backlight/*/brightness` で変える（実機で使えるか確かめる：§6 D2）。
- 明るさの値は設定（`chicken.env`）で変えられるようにする（`DISPLAY_BRIGHTNESS_DAY`・`DISPLAY_BRIGHTNESS_NIGHT` など）。

## 4. 本体との連携（おすすめ：別のプロセス＋状態ファイル）

```
main.py（本体） ──書く──> /run/nerukokko/display.json ──読む（0.2秒ごと）──> eyes（表示）
```

- 表示は**別のプロセス**（systemd の `nerukokko-eyes.service`）で動かす。表示が止まっても、アラーム・計測は止まらない。pygame を本体に入れずにすむ。岡田さんが本体と別に作り進められる。
- 本体は、状態が変わったときだけ `display.json` を書く（一時ファイルに書いてから置き換える＝読みかけの壊れたファイルを読まない）。
- 表示側は、ファイルがない・古い（例：2分以上更新がない）ときは「通常」を出す。

`display.json` の形（案）：

```json
{
  "mode": "sleeping",
  "speaking": false,
  "speech_kind": null,
  "illuminance_lux": 3.2,
  "updated_at": "2026-10-23T14:10:00Z"
}
```

| 項目 | 値 |
|---|---|
| `mode` | `alarm`・`listening`・`thinking`・`sleeping`・`evening`・`idle`（§2 の優先順で本体が1つに決める） |
| `speaking` | 話している最中なら `true` |
| `speech_kind` | 話している内容：`morning_summary`・`evening_suggestion`・`reply`・`alarm`、なければ `null` |
| `illuminance_lux` | 最新の照度。なければ `null` |
| `updated_at` | 書いた時刻（UTC） |

本体側（`display.json` を書く部分）は Claude、表示側（読んで表情を出す部分）は岡田さんの試作を使う、という分け方を考えている。

ほかの方法との比べ：

| 方法 | よい点 | 気になる点 |
|---|---|---|
| **別プロセス＋状態ファイル（おすすめ）** | 単純。表示が落ちても本体に影響しない。ファイルを見れば今の状態が分かる | 0.2秒ほど遅れる（表情なので問題ない） |
| 別プロセス＋ソケット | すぐ伝わる | つなぎ直しなどの処理が増える |
| 本体の中でスレッド | 1つのプログラムで済む | pygame の描画が重いと、BLE やアラームの処理が遅れるおそれ。Pi 3B では避けたい |

## 5. タッチ

- 最初は**使わない**（おすすめ）。眠っている人が触って誤操作するのを避けるため。
- 使うなら候補：画面をタップ＝トサカボタンと同じ（話しかける／アラームを止める）。ただし、アラームはたまごを巣に戻すまで止めないのが二度寝防止の仕組みなので、**タップでアラームは止めない**。

## 6. 実機で確かめること（決まったら `docs/hw-verification.md` に追加する）

| ID | 内容 | 合格の目安 |
|---|---|---|
| D1 | 本体（BLE・レーダー・送信）と表示を同時に1時間動かしたときの CPU と温度 | CPU 使用率の合計が 80% 未満。アラーム・BLE の取りこぼしがない |
| D2 | バックライトを 0・暗め・通常に変えられるか、暗い部屋でまぶしくないか | 記録中に画面が消える。暗い部屋で気にならない |
| D3 | 8時間つけっぱなしで落ちないか | 表示が止まらない（止まっても systemd が再起動する） |
